# Feature Specification: 将机器人唤醒词改为“小智，小智”

**Feature Branch**: `001-xiaozhi-wakeword`

**Created**: 2026-07-26

**Status**: Draft

**Input**: User description: "按 spec-kit 流程做 specify，我现在需要实现第一个二次开发的任务，注意阅读本机已经梳理的文档，在docs目录下： 任务是我需要改造这个机器人的应答模式，把之前的“hey, vector”改成对机器人说“小智，小智”，然后机器人就能响应我，接着就能回答我的问题。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 中文唤醒并回答问题 (Priority: P1)

作为机器人使用者，我希望对机器人说出“小智，小智”后，机器人能像原先听到“hey, vector”一样进入可响应状态，并继续回答我接下来的问题，这样我就能用中文唤醒词完成日常问答。

**Why this priority**: 这是这次二次开发的核心目标，没有这个能力就不构成可交付结果。

**Independent Test**: 在与当前系统相同的使用环境下，对机器人说“小智，小智”并紧接着提出一个普通问题；如果机器人成功进入响应状态并给出回答，则该故事独立成立。

**Acceptance Scenarios**:

1. **Given** 机器人处于可正常待命和联网工作状态，**When** 用户先说“小智，小智”再提出问题，**Then** 机器人应进入响应流程并给出与现有能力一致的回答。
2. **Given** 用户已经完成唤醒，**When** 用户提出一个当前系统本来就支持回答的问题，**Then** 机器人应沿用现有问答能力完成回复，而不是只识别唤醒词不继续应答。

---

### User Story 2 - 替换旧唤醒方式 (Priority: P2)

作为准备迁移到中文唤醒词的使用者，我希望系统把原来的“hey, vector”替换为“小智，小智”，这样新的交互方式清晰一致，不会同时存在两套默认唤醒口令造成困惑。

**Why this priority**: 用户已经明确提出“把之前的 hey, vector 改成小智，小智”，因此替换旧默认行为是本次需求的重要范围。

**Independent Test**: 在同一台已完成本次功能升级的机器人上，分别尝试旧唤醒词和新唤醒词；如果只有新唤醒词可以拉起响应流程，则该故事独立成立。

**Acceptance Scenarios**:

1. **Given** 系统已完成本次功能改造，**When** 用户仍然说“hey, vector”，**Then** 机器人不应再按旧默认方式被该短语唤醒。
2. **Given** 系统已完成本次功能改造，**When** 用户说“小智，小智”，**Then** 机器人应按新的默认唤醒方式进入响应流程。

---

### User Story 3 - 降低误触发和使用困惑 (Priority: P3)

作为日常使用者，我希望只有明确说出目标唤醒词时才触发机器人响应，这样可以减少误触发，也能让我更容易判断当前系统到底支持哪种唤醒方式。

**Why this priority**: 唤醒词属于高频入口，如果行为模糊，会直接影响日常使用体验和问题排查。

**Independent Test**: 用相近但不等同的表达尝试唤醒机器人；如果机器人不会轻易进入错误响应状态，则该故事独立成立。

**Acceptance Scenarios**:

1. **Given** 机器人处于待命状态，**When** 用户没有完整说出目标唤醒词，**Then** 机器人不应误进入完整问答响应流程。
2. **Given** 用户已学习新的唤醒方式，**When** 机器人被正确唤醒，**Then** 用户能够稳定复用这一交互方式，不需要依赖旧唤醒词兜底。

### Edge Cases

- 当用户只说出一次“小智”而不是完整的“小智，小智”时，系统如何处理？
- 当环境噪声较大、中文识别不稳定时，系统如何保证不会因为误识别而频繁误触发？
- 当机器人已被唤醒但后续问题没有被正确识别时，系统如何保持与现有失败处理一致？
- 当用户仍沿用旧习惯说“hey, vector”时，系统如何体现“旧唤醒词已被替换”这一行为变化？

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 将机器人的默认唤醒交互从“hey, vector”替换为“小智，小智”。
- **FR-002**: 用户 MUST 能在说出“小智，小智”后继续提出问题，并获得与当前系统既有能力一致的回答结果。
- **FR-003**: 系统 MUST 保持唤醒后的后续处理链路连续可用，不得出现“只能识别新唤醒词，但无法继续回答问题”的退化行为。
- **FR-004**: 系统 MUST 对旧默认唤醒词“hey, vector”停止作为本次功能中的默认唤醒入口。
- **FR-005**: 系统 MUST 在相同使用前提下，为用户提供可重复、可理解的中文唤醒体验，避免新旧两套默认唤醒方式并存造成混淆。
- **FR-006**: 系统 MUST 在用户未完整说出目标唤醒词时，避免轻易进入完整问答响应流程。
- **FR-007**: 本次功能 MUST 不要求用户重新配置与唤醒词无关的其他功能，才能继续进行正常问答。

### Key Entities *(include if feature involves data)*

- **唤醒词**: 用户用于让机器人进入响应状态的触发短语，本次需求中目标值为“小智，小智”。
- **唤醒后响应状态**: 机器人从待命进入可接收并处理后续问题的交互状态。
- **后续问题**: 用户在完成唤醒后提出的普通问题或当前系统已有能力支持的询问内容。

### 配置与兼容性影响（Configuration & Compatibility Impact）*(mandatory when settings, persisted data, or robot-facing behavior changes)*

- **受影响的配置/数据**: 机器人唤醒词行为及其等效配置；若项目通过持久化配置实现该能力，相关唤醒词设置也属于影响范围。
- **默认行为**: 功能完成后，用户默认通过“小智，小智”唤醒机器人并继续提问；“hey, vector”不再作为本次功能中的默认唤醒方式。
- **兼容性要求**: 除唤醒词本身发生替换外，现有问答能力、已配置的其他功能和无关设置必须继续可用。
- **迁移 / 回退说明**: 本次需求以替换默认唤醒词为目标，不要求用户先重做完整初始化；若后续实现需要额外迁移或回退入口，应在 plan 阶段明确写出。
- **待确认问题**: 无

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 在与当前系统原有唤醒条件等价的环境下，用户使用“小智，小智”发起唤醒并继续提问时，至少 90% 的尝试能够完成“成功唤醒并得到回答”的完整流程。
- **SC-002**: 在功能完成后的验证中，用户连续进行 10 次“小智，小智 + 提问”的基本交互，至少 9 次能够得到符合预期的响应结果。
- **SC-003**: 在同样的验证轮次中，旧默认唤醒词“hey, vector”不再作为主要唤醒入口生效，避免用户混淆新旧默认交互方式。
- **SC-004**: 用户在阅读一次功能说明或完成一次演示后，能够理解新的唤醒方式，并在 5 分钟内独立完成至少一次“小智，小智”唤醒后的问答操作。

## Assumptions

- 本次需求的目标是替换旧默认唤醒词，而不是同时长期保留“hey, vector”和“小智，小智”两套默认唤醒方式。
- 唤醒完成后的问答能力继续沿用现有系统已经支持的能力边界，本次需求不额外扩展新的知识问答能力。
- 本次需求聚焦于“用户如何唤醒并继续提问”的行为结果，具体落在哪一层实现将在后续 `plan` 阶段确认。
- 当前使用环境具备与现有机器人问答功能相同的基础前提，例如机器人已完成接入、系统可正常运行、原有问答链路可用。
